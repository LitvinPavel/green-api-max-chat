# MAX Web Messenger — GREEN-API Client (React + TypeScript)

> Тестовое задание на должность **«Фронтенд разработчик React»** для сервиса **[GREEN-API](https://green-api.com/)**.

> ℹ️ **О протоколе и реализации**: В соответствии с условиями тестового задания (*«допускается выполнение задания для WhatsApp или Telegram, если с MAX возникают сложности»*), сетевое взаимодействие реализовано по проверенному **GREEN-API HTTP API (WhatsApp-совместимый протокол)** с использованием методов `getStateInstance`, `sendMessage`, `receiveNotification` и `deleteNotification`. При этом пользовательский интерфейс спроектирован по образцу и дизайн-системе **[web.max.ru](https://web.max.ru/)** (фирменный акцент `#5b5ce2`, адаптивная верстка, карточки, бабблы).

## 🛠 Технологический стек

- **React 18** — компонентная архитектура, хуки (`useState`, `useEffect`, `useCallback`, `useRef`, `useMemo`).
- **TypeScript 5 (Strict Mode)** — строгая типизация запросов, ответов API, сообщений и состояний (без `any`).
- **Vite 5** — высокоскоростной сборщик и dev-сервер (с относительными путями `base: './'` для GitHub Pages).
- **Lucide React** — легковесные векторные пиктограммы.
- **Vitest** — модульные тесты ядра API (`GreenApiClient` с mock fetch), парсера вебхуков и утилит форматирования.
- **Чистый CSS / CSS Variables** — адаптивная стилизация в дизайн-системе web.max.ru без тяжелых сторонних фреймворков.

## 📩 Как проверить получение входящих сообщений через HTTP очередь

Для корректной проверки очереди уведомлений выполните следующие шаги:

1. **Проверьте настройки в консоли GREEN-API** ([console.green-api.com](https://console.green-api.com)):
   - Инстанс должен находиться в статусе **«Авторизован»** (`authorized`).
   - Поле **«URL для отправки уведомлений (webhookUrl)»** должно быть **ПУСТЫМ** (не заполнено). Если указан webhookUrl, GREEN-API будет слать сообщения на указанный URL, и очередь HTTP API будет пустой!
   - Опция **«Получать уведомления о входящих сообщениях (incomingWebhook)»** должна быть включена (**Да**).
2. **Войдите в веб-клиент**:
   - Введите ваш `idInstance` и `apiTokenInstance`.
   - В шапке появится статус: `● Авторизован`.
3. **Создайте чат**:
   - Нажмите `+` (Новый чат) и укажите номер собеседника (например, ваш личный номер или тестовый телефон).
4. **Отправьте ответ со второго телефона**:
   - Отправьте любое текстовое сообщение на номер инстанса со второго телефона.
   - Фоновый процесс веб-клиента (`receiveNotification`) автоматически считает сообщение из очереди, мгновенно отобразит его в ленте входящих (белый баббл слева) и подтвердит прочтение вызовом `deleteNotification(receiptId)`.

## 🔒 Безопасность и хранение данных (Security & Privacy)

- **Клиентский SPA**: Приложение не требует собственного бэкенда. Все запросы к GREEN-API отправляются напрямую из браузера (`fetch`) с поддержкой CORS.
- **Хранение сессии**: В демонстрационном SPA учетные данные и сообщения сохраняются в `localStorage` браузера пользователя для сохранения сессии при перезагрузке страницы.
- **Полная очистка («Забыть данные»)**: В выпадающем меню доступна функция **«Забыть данные и выйти»**, которая безвозвратно удаляет из браузера ключи инстанса, список чатов и историю сообщений.
- **Защита от утечек**: В кодовой базе, тестах и плейсхолдерах категорически исключены реальные персональные данные (номера телефонов, личные токены) — используются исключительно абстрактные примеры.
